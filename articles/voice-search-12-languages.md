AliExpress 向けの商品検索エンジンを個人で開発しています。ユーザーの言葉を LLM でマーケットプレイス向けの英語クエリに変換する仕組みで、そこに **12 言語の音声検索** を載せました。

作る前は「音声認識が一番難しいだろう」と思っていましたが、実際は逆でした。認識はブラウザがやってくれます。難しかったのは、その前後です。

## 1. 認識はブラウザに任せる

音声認識は Web Speech API（`SpeechRecognition`）をそのまま使っています。独自の音声パイプラインはありません。サーバーに音声を送らないので、コストもプライバシーの心配もありません。

認識言語（`recognition.lang`）の決め方だけは工夫しました。

```js
function voiceLang() {
  if (fallbackLang) return fallbackLang;   // ブラウザが「その言語は無理」と言った後
  if (userLang) return userLang;           // ユーザーが選んだ言語が最優先
  return deviceLang() || VOICE_LANG[pageLang];
}
```

- ページの言語より **端末の言語** を優先します。英語ページを開いたドイツ人は、ドイツ語で話すことが多いからです。
- `navigator.language` は `"he"` のように地域なしで返ることがあり、地域なしのタグを受け付けない認識エンジンもあるので、必ず `he-IL` のような形に補完します。
- ブラウザが言語を拒否した場合は、フォールバック先を覚えておきます。

## 2. 本当に難しいのは「話し言葉」を検索クエリにすること

入力された文章を見て驚きました。**話すと、人は長く、あいまいになります。**

> 「えーと、赤ちゃんのおしゃぶりを留めるクリップみたいなやつで、あんまり高くないの」

タイプ入力なら「おしゃぶりクリップ」で済むところです。この文をそのまま検索に投げると、ノイズだらけの結果になります。そこで、タイプ入力と共通の「意図を解釈する層」の前に、**話し言葉専用の前処理** を置きました。

- つなぎ言葉（「えーと」「みたいなやつ」）を取り除く
- 「あんまり高くない」は検索語ではなく **価格フィルター** に変換する
- 残った「商品＋修飾語」だけを、マーケットプレイスの出品タイトルで使われる短い英語クエリにする

音声検索とは、要するに **多言語検索と同じ問題**（人の言葉をマーケットプレイスの言葉に変換する）に、あいまいさが一段加わったものでした。

## 3. ラベルのないマイクボタンは、誰にも押されない

最初は検索バーの横に 🎤 の絵文字を置いただけでした。数日間、**押した人はほぼゼロ** でした。隣のカメラボタンと同じ形・同じ灰色だったので、機能ではなく飾りに見えていたのだと思います。

オレンジのアイコンの下に「音声検索」という **言葉** を各言語で添えた、縦長のボタンに変えました。ラベルを横に並べるとスマホ（幅 375px）で入力欄が狭くなりすぎるので、アイコンの **下** に積んでいます。最も長いポーランド語でも横スクロールが出ないことを実測しました。

## 4. Firefox ではボタンを「隠す」のではなく「説明する」

Firefox は `SpeechRecognition` をサポートしていません。そこで最初は、未対応ブラウザではボタンを表示しないようにしていました。「押しても動かないボタン」を見せたくなかったからです。

ところが、あるドイツのユーザーのセッション録画を見ると、Firefox Mobile を使っていました。ドイツは Firefox のシェアが比較的高い国です。つまり、**他のサービスにない一番の機能が、その国のユーザーには存在しないのと同じ** 状態でした。

今はボタンを常に表示し、未対応ブラウザで押された場合は「Chrome・Edge・Safari・Samsung Internet で使えます（Firefox は音声認識に未対応です）」という説明を、そのユーザーの言語で出しています。

```js
button.addEventListener("click", () => {
  if (!("SpeechRecognition" in window || "webkitSpeechRecognition" in window)) {
    showNote(t("voiceUnsupported"));   // 隠さずに、理由と代わりの方法を伝える
    return;
  }
  startRecognition();
});
```

## まとめ

- 音声認識そのものは Web Speech API で十分。難しいのは **話し言葉を検索クエリに整えること**。
- 認識言語は **端末の言語 → ページの言語** の順に決め、地域付きのタグにする。
- **ラベルのないアイコンは押されない。** 機能名を言葉で書く。
- 未対応ブラウザでは **隠すより説明する**。隠すと、その機能は存在しないのと同じになる。

### 日本語について

この記事を書いている途中で、穴に気づきました。認識言語の候補がサイトの 12 言語（英語・ヘブライ語・アラビア語・ドイツ語など）だけだったため、**端末が日本語でも、英語ページでは英語として認識されていました。** 上の `deviceLang()` は「候補にある言語なら端末の言語を使う」という作りなので、候補に無い日本語は黙って英語に置き換わっていたわけです。

候補に日本語・韓国語・中国語・タイ語・ギリシャ語・インドネシア語・ベトナム語・オランダ語・チェコ語を追加し、端末の言語が日本語なら `ja-JP` で聞くようにしました（2026 年 9 月 24 日）。認識された日本語はそのまま検索エンジンに渡り、英語のクエリに翻訳されます。ハングルや日本語が翻訳されずに通ってしまっていた、もう一つの問題は[こちらの記事](https://qiita.com/skazi1976/items/1818e60abaf10b806f9a)に書きました。
